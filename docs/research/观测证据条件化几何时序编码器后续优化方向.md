# 观测证据条件化几何时序编码器：后续优化方向

_研究路线文档 · 初稿 2026-10-14；主贡献收束修订 2026-10-17 · 面向缺失历史轨迹的行人未来多模态预测_

## 0. 文档定位

本文档用于记录当前 `GAST-PF` 架构后续优化的唯一实施路线，供后续代码 agent 按阶段阅读和实现。本文档只提出方案，不修改代码，也不恢复已经删除或否定的实验分支。

当前工作名称为：

> **观测证据条件化几何时序编码器**  
> **Observation-Conditioned Geometry-Temporal Encoder，简称 OCGT-ENC**

本文的主机制统一命名为：

> **观测证据条件化时空路由**（Evidence-Conditioned Spatiotemporal Routing，简称 ECSR）

OCGT-ENC 不是把 `UniTraj`、`GSM`、`Temporal Decay` 和双向 `Mamba` 简单拼接。其唯一主贡献应收束为 ECSR：将观测有效性与缺失年龄建模为共享的证据状态，并用同一证据状态控制不同信息流的资格、强度和读出。

ECSR 围绕一个任务特定问题重新组织这些机制：

> **当历史轨迹存在遮挡、中断或末端缺失时，哪些观测可以作为可靠证据参与空间交互、时间状态传播和最终状态读出？**

后续方法的创新重点应放在“观测证据如何改变信息传播”上，而不是把某个通用模块本身声称为原创。

核心原则是：

> **缺失观测可以消费上下文，但不能伪装成可靠的直接观测向外制造证据。**

相对几何、缺失年龄门控、双向融合和证据读出不再作为四个并列创新点，而是 ECSR 在关系传播、时序状态、方向路径和最终读出上的四个落点。

## 1. 当前模型和已确定边界

### 1.1 当前正式模型是 `GAST-PF`

> **术语统一**：`GAST-PF` 即**本文方法**（`encoder_type=gast`，`conf` 默认）；历史实验产物目录名沿用旧标签 `UT-ENC`（仅路径，非方法名），本文一律称 GAST-PF。

当前新架构由 `TrajectoryForecaster` 通过 `encoder_type` 选择：

```text
encoder_type = m0     -> M0 原始历史编码器
encoder_type = gast   -> GAST-PF 完整替换臂
```

主要代码位置：

| 内容 | 当前文件 |
| --- | --- |
| `GAST-PF` 主体 | `src/model/layers/gast_encoder.py` |
| 编码器选择和 decoder 接口 | `src/model/trajectory_forecaster.py` |
| 历史数据字段、`x_centers`、`x_angles` | `src/datamodule/ethucy_benchmark_dataset.py` |
| 模型开关 | `conf/model/missing_aware_ethucy_model_forecast.yaml` |
| TrajGap 实验入口 | `scripts/训练与评估/run_trajimpute_experiments.py` |

### 1.2 当前 GAST-PF 数据流

当前输入首先在 `TrajectoryForecaster.forward` 中组成四维历史特征：

```text
hist_feat = [x_positions_diff, x_velocity_diff, x_valid_mask]
          = [位移差分 2 维, 速度变化 1 维, 有效性掩码 1 维]
```

张量形状为：

```text
hist_feat       [B, N, T, 4]
valid_mask      [B, N, T]
key_padding     [B, N]
```

随后进入：

```text
逐帧 GSM 空间注意力 + ghost token
        ↓
前向/后向 missing-run delta
        ↓
Temporal Decay：x' = gamma ⊙ x
        ↓
前向 Mamba + 后向 Mamba
        ↓
两个方向输出直接相加
        ↓
固定读取最后时间步 y[:, -1]
        ↓
原有 FutureDistributionDecoder
```

`GAST-PF` 输出仍然是 `[B, N, embed_dim]`，后续 `FutureDistributionDecoder`、loss、指标和 TrajGap-Bench 协议保持不变。

### 1.3 当前借用内容和自有内容的边界

| 机制 | 当前处理 | 后续表述边界 |
| --- | --- | --- |
| GSM 逐帧空间注意力 | 从 UniTraj 借用并适配动态 actor 数量 | 不作为原创；作为 ECSR 的关系传播载体 |
| ghost token | 从 UniTraj 借用 | 只承担聚合上下文，不宣称是任务创新 |
| Temporal Decay | 从 UniTraj 借用，当前为 `exp(-ReLU(Linear(delta)))`；**即 Sports-Traj 论文的 BTS 模块，已完整移植** | 后续由 ECSR 的证据新鲜度路由替代，但二者同族——只能主张"恒等性修正"，不主张新的门控机制（见 §3.3 借用边界） |
| 双向 Mamba | 从 UniTraj 借用，两条独立栈后直接相加 | 后续由 ECSR 的路径证据融合控制 |
| 结构化未来分布 decoder | 原有组件 | 保持不变，作为公平比较接口 |
| TrajGap-Bench | 当前任务协议 | 保持不变，所有阶段统一评测 |
| `x_centers`、角度等几何字段 | 数据层已有，GAST-PF 尚未使用 | 作为 ECSR 关系路由的几何条件 |

以下内容不恢复、不作为后续路线：

- 已删除的 `CondDeltaMamba`；
- 原 ODMR/M0 增量模块及其失败实验分支；
- M1 概率校准路线；
- 重建辅助分支；
- split-conformal 校准；
- UniTraj 的 Future Encoder、CVAE 潜变量和 diverse loss；
- 将原论文完整移植后直接包装为新方法。

### 1.4 当前已暴露的结构问题

1. `GAST-PF` 主要看到位移差分、速度差分和 mask，缺少明确的绝对或相对空间几何。
2. `GAST-PF` 没有使用数据层已有的 `x_centers` 和末端方向信息，也没有显式使用 anchor lag。
3. 当前 GSM 的 `key_padding_mask` 只能屏蔽 padding actor，不能表达“当前帧的缺失 actor 不应作为可靠 key”。
4. 当前 `Temporal Decay` 可能衰减有效帧，不能保证全有效输入时严格保持 `gamma=1`。
5. 当前前向、后向 Mamba 输出直接相加，没有根据两侧观测证据的可靠程度动态融合。
6. 当前固定读取 `y[:, -1]`。当末端存在缺失时，最后时间步存在可靠性风险，但不能据此直接认定读出位置是主要瓶颈；历史实验已经表明，简单替换为 `last-valid` 并不能稳定解决问题。
7. 当前 actor 关系主要由内容注意力隐式学习，没有显式的 focal–neighbor 相对位置、相对运动和方向关系。

### 1.5 当前初步结果的使用方式

已有 ETH-M 初步结果如下，当前只能视为探索性筛选，不足以证明 `GAST-PF` 已经有效：

| 指标 | M0 | GAST-PF |
| --- | ---: | ---: |
| `minADE20` | 0.6145 | 0.6191 |
| `minFDE20` | 0.8532 | 0.8544 |
| `ADE@1` | 1.4034 | 1.4232 |
| `FDE@1` | 2.4877 | 2.4693 |
| `MR` | 11.97% | 11.91% |

结论是：整体基本持平，不能把性能变化归因于任一借用模块。后续仍采用单变量递进和配对实验，但实验目的从“比较五个独立创新”改为“定位 ECSR 的必要落点，并验证共享证据状态是否优于普通 mask 特征或独立控制器”。

### 1.6 既有读出实验的边界

项目此前已经在旧 M0 的 Easy/Hard screening 中比较过：

```text
固定末帧读取（fixed-last）
vs.
最后有效状态读取（last-valid）
```

结果是 Hard 场景出现局部正向信号，但 Easy 场景回归；收益没有集中在
`valid_count=1` 或末端缺失样本。因此该实验已经否定了“只读取最后有效状态即可解决缺失读出问题”的简单方案，`last-valid` 不作为后续主方法组件。

该结论不能反过来证明固定末端读出完全没有问题。它只说明：

1. 末端缺失可能造成状态可靠性风险，但读取位置本身未被证明是主要瓶颈；
2. `last-valid` 是一个过于粗糙的离散选择，不能同时处理可靠性与时间新鲜度的冲突；
3. 后续若继续研究读出，只能验证 `last + evidence` 的自适应融合，不能把 `last-valid` 重新包装成新模块。

另外，旧 CMAS/dt 实验中曾观察到 terminal-missing 子组退化，但该实验对应的是“缺失帧仍写入 selective scan 状态”，不是读出位置实验。因此不能把该结果直接归因于固定 `y[:, -1]`。

## 2. 核心研究假设：缺失不是普通输入值

缺失历史的关键问题不是“把一个值填成什么”，而是“这个位置能不能作为证据被其他位置使用”。因此后续方法统一采用 ECSR，而不是把五个模块作为并列创新。

ECSR 对每个 actor 和时间步维护同一个观测证据状态：

```text
m_i,t = 1                  直接观测有效
m_i,t = 0                  当前观测缺失
a_i,t = 0                  有效帧的缺失年龄
a_i,t = a_i,t-1 + 1       缺失帧的缺失年龄（令 a_i,-1 = 0）
```

由此得到软证据可靠度：

```text
r_i,t = m_i,t
        + (1 - m_i,t) * exp(-tau * a_i,t)
```

同时保留直接证据资格：

```text
s_i,t = m_i,t
```

两者语义不同：

- `s_i,t` 是硬资格，决定 actor 是否可以作为可靠 source/key；
- `r_i,t` 是软可靠度，决定缺失输入进入时序状态、方向路径和最终读出的强度；
- 缺失 query 可以接收有效邻居和 ghost token 的上下文，但不会因此获得直接观测 source 资格；
- padding actor 永远不参与消息传播。

ECSR 的统一原则是：

> **缺失观测可以消费上下文，但不能伪装成可靠的直接观测向外制造证据。**

目标数据流为：

```text
原始历史轨迹、有效性 mask、缺失年龄、几何条件
        ↓
共享观测证据状态 (s, r)
        ↓
证据源资格控制：谁可以发送空间消息
        ↓
关系路由：相对几何调节有效消息的 attention bias
        ↓
证据新鲜度控制：缺失输入按年龄衰减
        ↓
路径路由：按前向/后向证据量融合状态
        ↓
读出路由：在最新状态与历史证据之间自适应选择
        ↓
原有结构化未来分布 decoder
```

## 3. 核心机制：观测证据条件化时空路由

本节的四个小节是 ECSR 的四个信息流落点，不是四个独立贡献。实验阶段可以逐个启用以完成归因，但最终论文只将 ECSR 作为一个主机制。

### 3.1 统一证据状态与源资格

对于时刻 `t` 的 query actor `i` 和 source/key actor `j`，采用如下语义：

```text
query actor i 可以接收有效 actor j 的消息
缺失 actor j 不作为可靠 key 参与消息聚合
缺失 query actor i 仍可从有效邻居和 ghost token 接收上下文
padding actor 永不参与消息传播
```

空间消息的源资格为：

```text
allowed(i, j, t) = s_j,t and not padding(j)
```

ghost token 单独保持可用。该规则只限制 source/key，不删除 query，因此允许缺失 actor 利用社会上下文，同时避免缺失占位值污染有效 actor。

实现要求：

- 不能只使用统一的 `[B, N]` `key_padding_mask`；它无法表达逐时间步的缺失 source。
- 若使用 `nn.MultiheadAttention`，需要构造逐帧 pairwise attention mask，或改写为显式 QKV logits 计算。
- attention mask 必须同时处理 ghost、padding 和当前帧 source 资格。
- 无效 actor 的输出最终仍应乘以 padding mask 置零。

### 3.2 关系路由：相对几何作为条件

相对几何不是独立的第二个创新，而是 ECSR 在空间关系路由中的条件变量。每个时间步、每一对 actor 构造：

```text
relative_geometry(i, j, t) =
[
    dx_ij, dy_ij,
    log(1 + distance_ij),
    dvx_ij, dvy_ij,
    cos(heading_i - heading_j),
    sin(heading_i - heading_j)
]
```

关系 logits 为：

```text
b_ij,t = GeometryMLP(relative_geometry(i, j, t))
score_ij,t = q_i,t · k_j,t / sqrt(d) + b_ij,t
```

只有满足 `allowed(i,j,t)` 的 source 才能参与 softmax。相对几何只在 query 与 source 都有直接位置观测时计算；只要其中一方缺失，就将几何 bias 置为中性值 `0`，避免把占位坐标当成真实关系。建议 `GeometryMLP` 输出每个 attention head 的标量 bias，而不是直接生成高维 value，避免几何分支替代内容消息。

纪律：

- invalid 或 padding 的几何值可以置零，但必须由源资格规则阻止其作为可靠 key；
- Stage 4 主实验先只加入几何，不提前把缺失年龄混入几何分支；
- 位置和速度尺度必须与当前数据预处理一致，不在模块内部偷偷改变坐标系。

### 3.3 状态路由：证据新鲜度门控

ECSR 使用统一的 `r_i,t` 替换当前通用 `Temporal Decay` 的语义。其约束为：

- 有效帧严格满足 `r_i,t=1`；
- 缺失帧随 `a_i,t` 单调衰减；
- 令 `tau=softplus(theta)>0`；第一版采用全路由共享轻量参数，不为每个下游阶段建立独立可靠性网络。

进入前向和后向 Mamba 前：

```text
x'_i,t = r_i,t * x_spatial_i,t
```

重要边界：

```text
该门控只调节进入 Mamba 的证据强度，
不等价于修改 selective scan 的离散化步长 Δ，
也不声称实现了缺失期间严格 skip-update。
```

**借用边界（2026-10-19 补记）**：本节与 Sports-Traj / UniTraj 的 BTS 模块**同族**——BTS 同样是 `gamma = exp(-ReLU(MLP(delta)))` 在 Mamba block 前缩放输入特征，且已完整移植进基础版 GAST-PF（`gast_encoder.py::missing_run_deltas` + `TemporalDecay`，逐行对照官方代码）。**因此"按缺失年龄门控 Mamba 输入"不能作为 ECSR 的创新点主张**，本节只能表述为"对 BTS 式衰减的恒等性修正"（有效帧严格 `r=1`，BTS 在观测点仍衰减）。ECSR 的差异化主张限定在 §3.1 逐帧 source 资格、§3.2 几何 attention bias、§3.4 路径加权融合与可靠度读出。详见 `docs/results/stage2_frame_geo.md` §8.4。

### 3.4 路径与读出路由

双向 Mamba 不再无条件相加，而是根据同一证据状态在两条路径之间分配权重。为保证全有效输入时回到原有的直接相加，定义两条路径的缺失证据负担：

```text
D_forward(i,t) = sum_{s <= t} (1 - r_i,s)
D_backward(i,t) = sum_{s >= t} (1 - r_i,s)

[alpha_forward, alpha_backward]
    = softmax([-D_forward, -D_backward])

h_i,t = alpha_forward * h_forward_i,t
      + alpha_backward * h_backward_i,t
```

实际融合输出为 `2 * h_i,t`。缺失负担越大的方向权重越低；全有效时 `D_forward=D_backward=0`，两侧权重均为 `0.5`，尺度恢复后得到原来的 `h_forward + h_backward`。第一版不额外引入独立 `ReliabilityNet`；如果后续需要轻量可学习校准，也必须共享 ECSR 的证据输入并保持单调约束。

最终读出同样使用 `r_i,t`：

```text
w_i,t = softmax_t(ReadoutScore(h_i,t) + beta * log(r_i,t))
h_evidence_i = sum_t w_i,t * h_i,t
h_final_i = r_i,T * h_last_i + (1 - r_i,T) * h_evidence_i
```

这不是简单替换为 `last-valid`：有效末端保留最新动态，末端缺失时才增加历史证据。此前 `last-valid` 的不稳定结果仍作为负对照，不得重新包装成主方法。

本节的条件性假设是：如果共享证据状态能在末端缺失、邻居缺失和连续缺失子组稳定改善，同时不损害全有效子组，才说明 ECSR 解决了可靠性与时间新鲜度之间的冲突。

## 4. 分阶段实施顺序

阶段是 ECSR 的工程归因与消融顺序，不代表多个独立方法或贡献。每一阶段先完成代码、行为测试和小规模 sanity run，再决定是否进入下一阶段；未通过验收的落点不进入最终 ECSR。

**当前进度**：Stage 0 审计已完成，但新口径配对 M0 基线仍缺；Stage 1 AnchorGeo 已完成并进入 Stage 2；Stage 2 FrameGeo 已完成并判 No-Go（几何通道被使用但无机制性收益，MR 恶化，分层不支持几何假说，且容量/几何归属未分离）。下一步不再堆叠几何模块，优先补齐机制归因所需的对照臂与同口径配对基线。在配对基线补齐前，不得作最终因果或竞争力结论。

### Stage 0：GAST-PF baseline audit

**目标**：确认当前 `GAST-PF` 是可复现的比较起点，而不是直接在不稳定基线上堆模块。

**实施措施**：

1. 固定当前 `M0` 和 `GAST-PF` 的 decoder、loss、optimizer、数据 split、seed 和 checkpoint 选择规则。
2. 复跑至少一个主场景，并保存 `minADE20`、`minFDE20`、`ADE@1`、`FDE@1`、`MR`。
3. 按 `missing_count`、`valid_count`、`anchor_lag`、`forecast_gap`、`terminal_missing` 和连续缺失长度分组统计。
4. 为 `GAST-PF` 记录参数量、显存、训练时间和输出张量形状。
5. 确认当前 `Temporal Decay`、双向输出和固定末端读出确实对应代码，而不是依赖文档描述。
6. 将历史 `last-valid` screening 作为已知负对照记录，不把它当作新的主实验；后续读出实验必须围绕自适应融合展开。

**验收**：

- `M0` 和 `GAST-PF` 的相同协议复现可作为机制归因前提；若当前不具备，应明确登记为未满足，不得用不匹配结果替代；
- 没有 NaN、空 actor、padding 泄漏；
- 能得到 terminal missing 子组结果；
- 仅当 Stage 0 通过，才继续 Stage 1。

### Stage 1：AnchorGeo

**目标**：最低风险地把已有的 anchor 空间和末端方向信息接入 `GAST-PF`，验证“空间几何缺失”是否是主要瓶颈。

**新增输入**：

```text
x_centers                  [B, N, 2]
cos/sin(last_valid_angle)  [B, N, 2]
anchor_lag_norm            [B, N, 1]
```

`anchor_lag_norm` 可先由 `x_valid_mask` 在模型侧计算：

```text
last_valid_index = max{t | m_i,t = 1}
anchor_lag = (T - 1) - last_valid_index
anchor_lag_norm = anchor_lag / max(T - 1, 1)
```

**具体改造位置**：

- 在 `TrajectoryForecaster.forward` 或 `GASTEncoder` 内增加 `AnchorGeoProjection`；
- 先只在 GAST-PF 的 actor 输出端加入几何投影，不改变 GSM attention；
- 对 padding actor 的几何输入和输出显式置零；
- 保持 decoder 输入维度不变。

**对照**：

```text
GAST-PF
GAST-PF + AnchorGeo
```

**判定**：如果整体不升但 terminal missing 或长缺失子组改善，可保留并进入 Stage 2；如果所有子组均无改善，停止继续堆叠几何模块，先检查坐标尺度和数据泄漏。

**执行状态（2026-10-17 完成）**：已实现 `AnchorGeoProjection`（actor 输出端残差，输出层零初始化）+ `gast_anchor_geo` 开关（默认关闭，基础版本不变）；行为测试 14 项通过；smoke 全链路通过；五场景正式训练与评估完成（`outputs/stage1_anchor_geo_seed2024`）。详见 `docs/results/stage1_anchor_geo.md`。

**Stage 1 判定：Go（进入 Stage 2）**。宏平均整体不升（minADE20 −0.7%，其余 +0.6%~+7.9%），但 `terminal_missing=true` 子组改善（minFDE −0.6%、MR −7.5%），且 `anchor_lag` 收益随缺失年龄单调增大（lag 7：minFDE −7.6%、MR −13.8%），符合机制预期。需记录的负信号：完整历史轻微退化（lag=0 MR +9.9%、`missing_count=0` MR +20.6%）；MR 相对 MoFlow 由优转劣（4.86% vs 4.60%）；ETH-M 异常退步（minFDE +10.1%）。

> 说明：本轮按用户裁定，Stage 1 的**主对照**为外部模型 MoFlow、SocialLSTM；`GAST-PF` vs `GAST-PF+AnchorGeo` 的单变量配对归因留待消融阶段按同口径补跑。

### Stage 2：FrameGeo

**目标**：把逐帧位置几何显式送入 GSM，而不是只在最终 actor token 上补位置。

**建议特征**：

```text
relative_position_i,t = x_positions_i,t - x_centers_i
```

新增后的历史输入可先采用：

```text
[x_positions_diff(2), x_velocity_diff(1), valid_mask(1), relative_position(2)]
```

即 `input_dim=6`。第一版不要同时加入复杂速度向量、场景地图或额外社会标签。

**具体改造措施**：

1. 在数据侧确认 `x_positions` 的坐标已经经过当前协议需要的变换。
2. 由每个 actor 的最后有效位置作为 anchor，构造逐帧相对位置。
3. 缺失帧的几何输入置零，但保留 `valid_mask`；不能用未来 target 或插值后的真实位置。
4. 修改 `GASTEncoder` 的 `input_dim` 配置，不要硬编码为 4。
5. 记录全有效子组和不同缺失等级的变化，避免几何输入改善只是因为输入维度增加。

**判定**：只有在相对位置打乱实验能使结果发生预期变化、而 actor permutation 不改变结果时，才说明模型确实在利用几何关系。

**Stage 2 判定：No-Go（不晋级 Stage 3）**。两条行为测试均通过（打乱逐帧相对位置改变输出、邻居置换不改变 focal 输出），说明模型确实在读这两个通道；但结果层面无机制性收益：宏平均仅 minFDE20 改善 −1.06%，minADE20 +0.47%、ADE@1 +1.11%、FDE@1 +0.31% 变差，MR 4.86% → 5.15%（+5.92%），相对 MoFlow 的 MR 劣势由 +5.7% 扩大到 +11.9%；ZARA2-M 单场景崩坏（ADE@1 +21.04%、FDE@1 +18.29%、MR +34.80%）。分层证据不支持几何假说：`missing_count=0` 无缺失组也改善 −1.42%，与有缺失组同量级；`anchor_lag` 无单调剂量—效应（lag 0 −2.30%、lag 7 +0.17%）。该形态与"输入 4→6 维带来的全局表示容量提升"一致。限制：无噪声通道对照臂，容量与几何的归属未直接实验分离；本轮训练用 `LAPLACE_LOSS_IMPL=vectorized-batch-v1`（等价性门禁 38/38 PASS），与 Stage 1 数值路径不同。详见 `docs/results/stage2_frame_geo.md`。

### Stage 3：Missing-Key Mask

**目标**：实现 ECSR 的第一条硬路由规则，阻止当前缺失 actor 的占位特征作为可靠 source/key 污染有效 actor。

**实现措施**：

1. 修改 `GSMAttnBlock`，让 attention mask 从 `[B, N]` 扩展为逐帧 `[B, T, N]`。
2. ghost token 始终作为可用 key；padding actor 始终屏蔽。
3. 当前帧缺失 actor 不作为 actor key；缺失 query 仍可读取有效 actor 和 ghost。
4. 如继续使用 `nn.MultiheadAttention`，构造 `[B*T*num_heads, N+1, N+1]` 的 logits mask；否则实现显式 QKV attention。
5. 对全缺失邻居帧设置安全路径：至少保留 ghost token，不能产生全 `-inf` 的 attention 行。

**必须测试**：

- 改变缺失 actor 的占位值，valid actor 输出应近似不变；
- 改变 padding actor 的值，valid actor 输出必须不变；
- actor 槽位随机置换，集合输出应按置换对应；
- 全有效输入与当前 baseline 的 mask 路径不能出现意外屏蔽。

**判定**：若行为测试不通过，不进行 Stage 4；优先修正 mask 语义和 attention 数值稳定性。

### Stage 4：Relative Geometry Bias

**目标**：实现 ECSR 的关系路由条件，使关系建模显式依赖 focal–neighbor 的相对空间和相对运动，而不是只依赖 token 内容。

**实现措施**：

1. 在 `GSMAttnBlock` 中根据逐帧位置和位移构造 `[B, T, N, N, F_rel]`。
2. 用 `GeometryMLP(F_rel -> num_heads)` 生成每个 head 的关系 bias。
3. 将 bias 加到 attention logits，再叠加 Stage 3 的缺失/padding mask。
4. 几何 bias 只调节 attention 权重，不直接替代 value 分支。
5. 对距离、相对位移做与当前数据一致的尺度归一化，并记录归一化方式。

**负对照**：

- 随机打乱邻居相对几何，但保持 token 和 mask 不变；
- 交换 actor 槽位但同步交换几何；
- 只保留距离、去掉方向；
- 只保留方向、去掉距离。

**判定**：若随机几何与真实几何结果无差别，不能宣称关系模块有效；若 actor permutation 失败，停止并修复集合语义。

### Stage 5：Evidence-Age Gate

**目标**：实现 ECSR 的共享证据新鲜度状态，将当前通用 Temporal Decay 替换为“有效帧恒等、缺失帧按年龄衰减”的任务特定门控。

> **借界提醒**：当前 Temporal Decay 就是 Sports-Traj 的 BTS（已完整移植）。本阶段产出属**同族改良**，只能表述为"对 BTS 式衰减补上有效帧恒等约束"，不能作为新的缺失门控机制主张。见 §3.3 与 `docs/results/stage2_frame_geo.md` §8.4。

**实现措施**：

1. 新增独立的 `missing_age` 计算函数，不复用当前“观测点从 1 起算”的 delta 作为严格语义。
2. 实现 `EvidenceAgeGate`，输入 `[B, N, T]` 的 mask 和 age，输出 `[B, N, T, C]` 的 gate。
3. 先采用全路由共享的轻量 `tau`，确保空间源资格、时序门控、方向融合和读出使用同一证据状态；不得为每个落点各自训练独立可靠性网络。
4. 在进入前向和后向 Mamba 前分别按对应方向的 age 施加 gate。
5. 保留旧 `Temporal Decay` 作为实验对照，不要在同一版本同时存在两个衰减机制。

**必须测试**：

- 全有效 mask 时 `gate` 逐元素严格等于 1；
- 单个缺失后 age 增大时 gate 单调不增；
- mask 全 0 的 actor 不产生 NaN；
- padding actor 输出仍为零；
- 不使用 future target 计算 age。

**边界**：该阶段只验证输入证据衰减，不把它表述成改变 Mamba 的 `Δ` 或严格 skip-update。

### Stage 6：Direction Reliability Fusion

**目标**：实现 ECSR 的路径路由，让双向 Mamba 根据同一证据状态在前、后向路径之间自适应融合。

**实现措施**：

1. 修改 `TemporalEncoder._run` 或其调用接口，使其返回 `y_forw`、`y_back`，不要立即相加。
2. 将后向输出翻转回原时间顺序。
3. 从共享 `r_i,t` 构造前、后向缺失证据负担，不再为方向融合单独建立一套可靠性输入语义。
4. 对负担取负后做 softmax，并用尺度保持式融合；全有效时必须恢复原有输出和尺度：

```text
y = 2 * (alpha_forw * y_forw + alpha_back * y_back)
```

5. 记录 terminal missing 时两个方向的平均权重，作为可解释性诊断。

**判定**：如果权重基本恒定为 0.5 且没有任何缺失等级差异，可暂不保留该落点；如果权重出现极端塌缩，也应先检查共享证据状态和尺度归一化，而不是再增加独立控制器。

### Stage 7：Evidence-Aware Readout

**目标**：实现 ECSR 的最终读出路由，在不重复采用已判负的 `last-valid` 路线前提下，检验固定 `y[:, -1]` 是否在 terminal-missing 条件下存在可通过共享证据状态缓解的可靠性问题。

**实现措施**：

1. 保留完整 `[B, N, T, C]` 时序输出到读出层。
2. 用轻量 `ReadoutScore` 为每个时间步产生标量分数。
3. 以共享 `r_i,t` 的 `beta * log(r_i,t)` 调整分数，再沿时间维 softmax；不得重新定义一套独立的可靠性分数。
4. 得到 `h_evidence` 后，与 `h_last` 进行可靠性融合。
5. 对 padding actor 先做 mask，再计算读出；避免 padding 时间步进入 softmax。
6. 额外记录每个 actor 的 readout entropy、最大权重时间点和 terminal weight。
7. 将历史 `last-valid` 结果作为负对照：它可以出现在对照表中，但不得作为需要继续调参或组合的独立主线。

**对照**：

```text
fixed-last
last-valid
evidence-only
last + evidence-aware gate
```

其中 `last-valid` 只承担历史负对照作用，不要求重复旧 M0 训练；若因当前 GAST-PF 代码路径不同而重跑，必须标记为诊断实验，不能据此重新宣称该路线有效。不能只比较最终指标，必须报告：

- `terminal_missing=0` 与 `terminal_missing=1/≥2` 子组；
- `anchor_lag` 和连续末端缺失长度曲线；
- 全有效组是否保持不退化；
- 只改变末端缺失占位值时的预测稳定性。

只有在 `last + evidence-aware gate` 相比 `fixed-last` 在末端缺失组稳定改善、相比 `last-valid` 进一步解决时间新鲜度损失，并且全有效组不退化时，才可保留该机制。

### Stage 8：Full ECSR-OCGT-ENC

**目标**：只组合已经单独通过验收的 ECSR 落点，形成最终方法；这里的组合不是五个独立模块的堆叠，而是同一证据状态在不同信息流上的统一实例化：

```text
shared evidence state (s, r)
        ↓
source/key eligibility
        + relative-geometry relation bias
        + temporal freshness routing
        + directional evidence routing
        + evidence-conditioned readout
```

必须增加一个统一性对照：

```text
独立控制器版本：每个落点各自学习可靠性
共享 ECSR 版本：所有落点复用同一个 evidence state
```

组合时保持 decoder、loss、optimizer、数据协议和评测脚本不变。若共享 ECSR 反而下降，回退到最近一个通过单变量验收的落点，不继续增加新模块；若某个落点无稳定收益，则从最终方法中删除，只保留已经通过验证的 ECSR 子路径。

## 5. 统一实验纪律

### 5.1 不变项

每个阶段必须固定：

- `FutureDistributionDecoder`；
- loss 和多模态采样方式；
- TrajGap-Bench Mixed-train/val/test 协议；
- batch size、学习率、weight decay、epoch、warmup；
- fold、seed 和 checkpoint 选择规则；
- 数据归一化、坐标变换和未来 target；
- M0、GAST-PF 的报告指标口径。

### 5.2 必报指标

所有阶段至少报告：

```text
minADE20
minFDE20
ADE@1
FDE@1
MR
```

同时按以下字段做诊断：

```text
missing_count
valid_count
anchor_lag
forecast_gap
terminal_missing
连续缺失长度
neighbor_valid_ratio
focal-neighbor_joint_observation_age
scene macro / micro aggregate
```

建议额外记录：

- 参数量、显存峰值和训练时间；
- 完整历史（`missing_count=0`）子组；
- 末端缺失子组；
- 中间缺失后恢复观测子组；
- 高缺失等级子组；
- 预测轨迹的速度、加速度、曲率和转向变化。

### 5.3 必做行为测试

1. **缺失占位不敏感**：只改变缺失 actor 的占位位置或速度值，valid actor 输出不应产生不合理变化。
2. **padding 隔离**：只改变 padding actor 的输入，所有有效 actor 输出保持不变。
3. **证据源不伪造**：缺失 actor 可以接收有效邻居消息，但不能作为有效 actor 的可靠 source/key。
4. **几何有效性**：打乱真实 relative geometry 后，模型输出应发生可解释变化。
5. **全有效恒等**：全有效输入时 `r_i,t=1`，ECSR 不应意外改变基础 GAST-PF 的有效帧语义。
6. **集合不变性**：同步置换 actor 输入、mask 和几何后，输出按同样置换变化。
7. **末端缺失不泄漏**：读出和所有几何量不得使用 future target 或 future validity。
8. **缺失年龄单调性**：在其他输入不变时，连续缺失长度增加不应使 `r_i,t` 增大。
9. **共享状态一致性**：空间 source 资格、时序 gate、方向权重和读出 bias 必须来自同一 `missing_age` 与 evidence state。
10. **安全 attention**：任何合法输入都不能产生全 `-inf` logits、NaN 或空有效 key 集合。

### 5.4 归因规则

- 单个落点在主指标上提升，同时不损害 `missing_count=0` 和高缺失子组，才可进入 ECSR 组合。
- 只有改善内部 gate、attention 或权重可视化而不改善未来轨迹指标，不能作为成功。
- 不能把历史 `last-valid` 的局部正向结果解释为固定末端读出问题已经被证明；它只说明简单替换不是稳定解决方案。
- 只有单一场景提升，不足以支持方法级结论；至少需要多数主场景方向一致。
- 必须比较“共享 ECSR 状态”和“各落点独立控制器”；若共享状态没有稳定收益，不能宣称统一路由本身有效。
- 若落点增加参数但没有显著收益，应保留为失败记录，不继续叠加。
- 任何收益必须与 M0/GAST-PF 配对重训比较，不能用不同代码状态的结果直接做因果归因。

## 6. Go / No-Go 决策

### Go 条件

满足以下大部分条件，才进入下一阶段或形成完整方法：

- 相比对应基线，主指标有稳定改善或高缺失子组有明确改善；
- terminal missing 和连续缺失场景的收益符合机制预期；
- `missing_count=0` 完整历史子组没有不可接受的退化；
- 行为测试全部通过；
- 多数场景方向一致，而不是单一场景偶然提升；
- 能明确说明 ECSR 引入了什么不同于普通 mask 特征的证据传播规则；
- 共享 evidence state 相比独立控制器或普通 mask baseline 有稳定优势。

### No-Go 信号

出现以下情况时，应停止堆叠并记录失败：

- 方法只是再次拼接 `valid rate`、`missing count` 或 mask summary，没有改变传播或读出机制；
- simple zero/forward fill 已解释全部收益；
- 全有效输入明显退化；
- attention mask 破坏 actor permutation 或 padding 隔离；
- readout 只改善内部权重可视化，不改善 terminal missing 子组；
- 双向路径权重塌缩到单一方向且无法由共享证据状态解释；
- 几何模块对随机几何打乱不敏感；
- 结果只在一个数据场景或一个 seed 上提升；
- 共享 ECSR 比独立控制器更差，且无法通过消融定位冲突来源；
- 完整 ECSR 比最近一个通过验收的落点更差，且无法定位冲突来源。

若出现 No-Go，不应继续增加模块数量，而应收缩主张，转向“缺失历史下的系统评估与失败边界”，或只保留通过验证的 ECSR 子路径。

---

## 7. 后续论文叙事建议

最终论文不应写成：

> 将外部方法的 GSM、Temporal Decay 和双向 Mamba 直接拼接到现有预测框架中。

更合适的叙事是：

> 针对缺失历史轨迹预测中“无效观测可能被错误传播”的问题，提出观测证据条件化时空路由（ECSR）。ECSR 将观测有效性与缺失年龄统一为共享 evidence state，并用同一状态控制关系 source 资格、时序状态更新、双向路径融合和最终读出；相对几何作为关系路由条件，使缺失结构成为信息流控制变量，而不仅是输入特征。

创新边界应明确写为：

1. `GSM`、`Temporal Decay`、双向 `Mamba` 是借用的基础机制；
2. 本文的唯一主机制是 ECSR；缺失 key 隔离、相对几何偏置、证据年龄门控、方向融合和读出只是该机制的不同信息流落点；
3. ECSR 的核心可验证性质是证据源不伪造、缺失年龄单调衰减和全有效恒等；
4. 必须通过共享状态与独立控制器、普通 mask 特征和简单插值/填充的对照，证明统一路由不是模块堆叠；
5. 贡献是否成立取决于消融和行为测试，而不是模块数量或模型名称；
6. 若后续实验不能证明 ECSR 在缺失历史任务上有效，应收缩为系统评估与失败边界，不强行包装为方法创新。

---

## 8. 当前实现状态与后续验证

`GAST-PF-ECSR` 的 Stage 8 完整候选代码已落地：同一 evidence state 控制空间 source 资格、几何关系 bias、时序输入强度、双向路径融合和最终读出。实现与代码级验证记录见 `docs/results/stage2_frame_geo.md` 的 ECSR checkpoint。

代码实现完成不等于创新点已被实验验证。接下来应：

1. 在独立输出目录运行端到端 smoke，确认训练、checkpoint 保存/加载、评估和六维分层均完整；
2. 再跑五场景筛选实验，至少配对比较 `GAST-PF`、Stage 2 `GAST-PF-FrameGeo` 和 `GAST-PF-ECSR`；
3. 报告全场景汇总及 `missing_count=0`、高缺失、末端缺失分层，并保留每个 seed 的结果；
4. 只有满足预先定义的 Go 条件后，才做共享状态/独立控制器及各路由落点消融；
5. 保持 decoder、loss、数据协议不变，不恢复 `CondDeltaMamba`、ODMR/M0、M1 或重建辅助分支。

## 9. 当前结论

当前已经有可运行的 `GAST-PF-ECSR` 实现候选，但没有五场景实验结果，不能判断它是 Go 还是 No-Go，也不能声称性能提升。最终方法不应被描述为五个模块的叠加，而应验证一个共享证据状态驱动的 ECSR。代码实现已完成，实验归因仍按以下顺序组织：

```text
先补充显式几何
→ 再限制缺失证据传播
→ 再保证有效帧恒等、缺失帧按年龄衰减
→ 再做双向可靠性融合
→ 最后检验并修正末端缺失下的读出
```

最终组合应满足：

```text
同一个 evidence state
→ 控制 source/key 资格
→ 控制时序证据新鲜度
→ 控制前后向路径融合
→ 控制最终历史读出
```

其中读出阶段不再重复“固定末帧 vs 最后有效帧”的简单替换，而是把已有 `last-valid` 负结果作为边界，重点验证共享证据状态是否能够同时保留最新动态和可靠历史信息。只有当共享 ECSR 相比普通 mask、独立控制器和最近一个单落点版本都表现出稳定收益，并通过证据不伪造、年龄单调和全有效恒等测试，才将其作为最终方法主张。

## 10. GAST-PF-Tail：补回编码后场景推理

前述 GAST-PF 替换 M0 时，除了替换历史编码器，还同时移除了 M0 的编码后场景推理尾部。这会造成一个容易被忽略的架构差异：GAST 输出的是每个 actor 的独立 token，随后直接进入 decoder；M0 则会在 actor token 上叠加位置、朝向、actor type，并经过 5 层 actor-level self-attention。因此，即使 GAST 的历史时序编码更适合缺失观测，模型也可能缺少对“谁在谁旁边、相对运动方向如何影响预测”的显式场景推理。

本轮实现不恢复 M0 的历史输入投影和历史 Mamba，而是在 DAP 读出之后恢复 M0 的**编码后场景交互尾部**，形成单一、可归因的结构变体：

```text
逐帧 GSM
→ 双向 Mamba
→ DAP 时间读出
→ M0 actor context（x_centers、末端 cos/sin 朝向、actor type）
→ 5 层 Scene Transformer
→ FutureDistributionDecoder
```

### 10.1 结构定义

令 `h_i` 为 DAP 输出的 actor token，`p_i` 为 M0 原有的四维上下文：

```text
p_i = [x_center_x, x_center_y, cos(theta_last), sin(theta_last)]
c_i = MLP(p_i) + Emb(type_i)
z_i^0 = h_i + c_i
z_i^l = SceneBlock_l(z_i^{l-1}),  l = 1,...,5
z_i = LayerNorm(z_i^5)
```

为了避免新尾部在训练起点破坏已经验证过的 DAP 表征，实际输出采用零初始化残差插值：

```text
h_i^out = h_i + alpha_scene (z_i - h_i),    alpha_scene = 0 at initialization
```

`alpha_scene` 是可学习标量，记录在 checkpoint 中。这样可以区分两种情况：

1. `alpha_scene` 长期接近 0：DAP 已经足够，M0 场景尾部没有提供额外信息；
2. `alpha_scene` 稳定偏离 0 且指标改善：DAP token 确实需要编码后 actor-level 场景推理。

padding actor 在尾部输入、每层输出和最终输出都显式置零；decoder、loss、数据协议和 DAP 读出保持不变。

当前默认宽度 `embed_dim=128` 下，DAP 为 5,218,611 个参数，加入五层 M0 场景尾部后为 6,227,508 个参数，增加 1,008,897（约 19.3%）。因此这不是“零成本恢复”：首轮筛选应记录实际 epoch 时间和显存，再决定是否值得扩展多 seed。

### 10.2 实验开关

代码开关为 `gast_m0_scene_tail`，新增独立变体 `GAST-PF-Tail`。该变体基于 GAST-PF 并保留 DAP 读出，再接入 M0 场景尾部；默认 `GAST-PF`、`GAST-PF-DAP` 和 M0 均不受影响。它不加入 FrameGeo、ECSR 或 M0 历史 Mamba。

建议按以下顺序执行，避免再次扩大实验矩阵：

1. 先完成现有 `GAST-PF-DAP` 五场景筛选；
2. 以同一训练协议、同一 seed、同一 `val_new_minFDE20` 选点运行 `GAST-PF-Tail`；
3. 报告宏平均和逐场景 `minADE20`、`minFDE20`、`MR`，并按 `missing_count=0`、高缺失、末端缺失分层；
4. 同时记录 `alpha_scene`、参数量、单 epoch 时间和显存；
5. 只有筛选结果相对 DAP 稳定改善，才增加第二个 seed 或进行尾部深度/残差形式消融。

该变体的论文定位应是“缺失感知时空编码器与编码后场景推理的解耦融合”，而不是简单声称恢复了 M0。真正需要验证的是：在保持 GAST-PF 的缺失间隔建模能力的同时，`M0SceneTail` 是否恢复了 actor-level 关系推理，并在方向敏感场景或高交互场景中带来可重复收益。

### 10.3 第一版单向因果时序变体：GAST-PF-UniTail

为验证 GAST 的双向时序状态和 DAP 读出是否是性能瓶颈，新增第一版因果对照，不覆盖原有 `GAST-PF` 与 `GAST-PF-Tail` 的历史定义。其结构为：

```text
逐帧 GSM
→ 前向 gap-aware Mamba
→ 固定最后时间步读出
→ M0 actor context + 5 层 Scene Transformer
→ FutureDistributionDecoder
```

代码开关为 `gast_temporal_direction: unidirectional`，实验变体为 `GAST-PF-Uni` 和 `GAST-PF-UniTail`。单向版本只注册 `ssm_forw` 和 `norm_f_forw`，仅使用前向缺失衰减，输出固定历史末端状态 `y[:, :, -1]`；不使用反向 Mamba、反向衰减或双向 DAP。`GAST-PF-UniTail` 不再要求 `gast_directional_readout=true`，因为场景尾部接收的是通用 actor token，而不是 DAP 专属 token。

ECSR 在单向模式下保留为可选路径，但不再执行前后向路由，而是对前向状态使用 evidence-aware readout：共享 reliability 仍控制历史状态的时间证据权重，末端状态可靠时保持末端恒等，末端缺失时向可靠历史证据回退。首轮单向实验应优先使用 `GAST-PF-UniTail`，关闭 ECSR、FrameGeo 和 AnchorGeo，避免把时序方向变化与其他机制混杂。

推荐的第一轮对照为：

```text
GAST-PF       = 双向 Mamba + 固定末帧
GAST-PF-Uni   = 单向 Mamba + 固定末帧
GAST-PF-UniTail = 单向 Mamba + 固定末帧 + M0 场景尾部
```

其中 `GAST-PF` vs `GAST-PF-Uni` 隔离时序方向变化；`GAST-PF-Uni` vs `GAST-PF-UniTail` 隔离编码后场景尾部。既有 `GAST-PF-Tail` 是“双向 + DAP + 场景尾部”，读出也不同，不应拿它与 `GAST-PF-UniTail` 的差值单独归因于 Mamba 方向。

需要同时记录参数量和训练耗时：单向版本在相同 `gast_depth=4` 下约移除一套反向 Mamba，不能把收益或退化完全归因于方向性。必要时增加参数量匹配的单向深度对照，但不改变首轮结构定义。旧双向 checkpoint 不应直接加载到单向模型；评估脚本通过 `gast_temporal_direction` 做配置契约检查。
