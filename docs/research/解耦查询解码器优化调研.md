# 解耦查询解码器的优化方向调研

_2026-10-21 · 对象：GAST-PF 的 `FutureDistributionDecoder`（state query + mode query + 耦合）_

## TL;DR

**我们的解码器不是自研结构，它是 DeMo（NeurIPS 2024）的实现。** 仓库原名 DeMo 即来源于此。

DeMo 的原话：

> "we introduce DeMo, a framework that **decouples multi-modal trajectory queries into two types: mode queries capturing distinct directional intentions and state queries tracking the agent's dynamic states over time**. By leveraging this format, we separately optimize the multi-modality and dynamic evolutionary properties of trajectories. Subsequently, the mode and state queries are integrated to obtain a comprehensive and detailed representation of the trajectories."
> — arXiv:2410.05982 [1]

**这条路线有官方后续工作 DeMo++（arXiv:2507.17342，2025 年期刊扩展）**，它明确给出了"这套解耦架构该怎么继续优化"的答案。这是最有价值的参照，同时也意味着**直接复现 DeMo++ 的改动等于撞车**。

我们相对 DeMo++ 缺三样东西，其中两样可迁移：

| DeMo++ 的能力 | 我们 | 可迁移性 |
| --- | --- | --- |
| holistic motion intentions（mode query） | ✅ 有 | — |
| fine spatiotemporal states（state query） | ✅ 有 | — |
| **self-refinement capability（自精化）** | ❌ **无（单次前向）** | **高** |
| cross-scene trajectory interaction | ❌ 无 | 低（我们是单场景，无"相邻场景"） |
| hybrid Attention + Mamba | ✅ 有 | — |

## 1. 架构出处与我们的实现差异

### 1.1 DeMo 的原始设计

mode query（意图）× state query（动态状态）解耦，各自优化，再融合。实现用 Attention + Mamba 混合。

### 1.2 我们的实现

| DeMo 概念 | 我们的模块 | 输出 | 测试是否使用 |
| --- | --- | --- | --- |
| state query | `state_context_layers` + `timequery_embed_mamba` | `dense_predict` | ❌ 仅辅助监督 |
| mode query | `mode_self_attention_layers` + `mode_context_layers` + `mode_trajectory_head` | `y_hat` / `pi` / `scal` | ❌ 仅辅助监督 |
| mode-state 融合 | `coupling_*` × 3 + `coupled_temporal_mamba` + `coupled_trajectory_head` | `new_y_hat` / `new_pi` / `scal_new` | ✅ **唯一最终输出** |

**关键结构事实**：在 DeMo 中 mode queries 是最终轨迹输出的一部分；在我们这里，mode 分支和 state 分支的**输出全部被丢弃**，只有第三段耦合头的输出进入评估。

因此：

- 优化 mode 分支 / state 分支 → **只能通过辅助监督（deep supervision）间接起作用**；
- 优化耦合分支 → 直接影响四项指标。

这一条决定了后面所有方案的优先级。

## 2. DeMo++ 的官方改进（最相关）

arXiv:2507.17342，NeurIPS 2024 的期刊扩展版 [2]：

> "we propose DeMo++, a framework that decouples motion estimation into two distinct components: **holistic motion intentions** to capture the diverse potential directions of movement, and **fine spatiotemporal states** to track the agent's dynamic progress within the scene and **enable a self-refinement capability**. Further, we introduce a **cross-scene trajectory interaction mechanism** to explore the relationships between motions in adjacent scenes."

三个新增点：

1. **Self-refinement（自精化）** —— state 序列在场景中推进后能反过来修正自身。**我们完全没有**：`forward` 是单次前向，没有任何 refinement 迭代（代码里的 `for i in range(N)` 都只是 ModuleList 构造，不是推理迭代）。
2. **Cross-scene trajectory interaction** —— 相邻场景之间运动的关系建模。我们是单场景行人预测，**没有对应物，不适用**。
3. Hybrid Attention + Mamba —— 我们已有。

## 3. 可迁移的通用 query 训练技术

DeMo++ 之外，query-based 解码器（DETR 谱系）有两个被反复验证的稳定化手段：

**DN-DETR（CVPR 2022，arXiv:2203.01305）** —— query denoising。把带噪声的 GT 作为额外 query 送入解码器，要求重建原 GT。核心洞察是一对一/WTA 分配在训练早期不稳定，denoising 任务给了稳定梯度。

> 对我们的直接对应：我们用的正是**硬 WTA**（取误差最小 mode 回归）+ `CE(pi, argmin)`。aWTA 那篇 [3] 独立指出了同样的"初始化敏感"问题。DN-DETR 是另一条解法。

**Group DETR（ICCV 2023，arXiv:2207.13085）** —— 多组 query，组内一对一分配，组间共享参数、独立 self-attention。

> 原话："It resembles data augmentation with automatically-learned object query augmentation. It is also equivalent to simultaneously training parameter-sharing networks of the same architecture, introducing more supervision"。对我们相当于"K 个 mode × G 组"的组内 WTA。

## 4. 推荐方案（按杠杆排序）

### D1 · 耦合分支加自精化迭代（对应 DeMo++ 的 self-refinement）

在耦合表示 `mode_dense [B,M,T,C]` 之后加 1–2 轮 refinement：

```
h ← coupled_temporal_mamba(h)        # 现有
for _ in range(R):                    # 新增
    h ← cross_attn(h, encoding)       # 回到场景/actor 上下文
    h ← temporal_mamba(h)
    y_hat, pi, scal ← head(h)         # 中间监督（可选）
```

- **依据**：[2] 明确指出单次前向不足以建模轨迹的时空演化，并提出自精化；
- **改动面**：只在耦合分支加循环，不动编码器、不动 loss 结构（可加中间步的辅助 loss）；
- **直接影响**：四项指标（这是唯一直接影响最终输出的分支）；
- **验收**：minFDE20 与 ADE@1 至少一项改善 ≥1.5%，参数量增幅 ≤10%；
- **风险**：中。迭代次数是超参；R=2 时参数量几乎不变（共享权重），R>2 收益递减。

### D2 · Query 去噪（DN-DETR 思路）

在训练时加入带噪 GT 轨迹作为额外 query，要求重建。

- **依据**：[4] 对一对一分配不稳定的诊断与解法；我们的硬 WTA 有同类问题；
- **改动面**：训练期加 query + 重建 loss；推理不变；
- **直接影响**：间接（改善分配稳定性 → 更好的 mode 覆盖与置信度）；
- **验收**：不同 seed 的 best epoch 离散度下降 + minFDE20 改善；
- **风险**：低（纯训练期技巧），但**撞车风险高**（DETR 谱系的标准技巧，只能作 borrowed control）。

### D3 · 组内 WTA（Group DETR 思路）

K=20 个 mode 分成 G 组（如 G=4，每组 5 个），组内做 WTA，组间共享参数。

- **依据**：[5]；
- **改动面**：loss 的分配逻辑 + 一次 forward 复制；
- **风险**：低-中；同样属 borrowed control。

### D4 · 双头消融（结构清理）

Mode 分支 1,276,337 参数（总参数 24.5%）的输出在测试时被丢弃。删掉它，验证辅助监督是否真有正则作用。

- **依据**：工程冗余，无直接文献；
- **改动面**：删模块 + 去掉对应 loss；
- **验收**：四项指标不退化（≤0.3%），训练时间降 ≥15%；
- **风险**：中。退化本身就是有价值的负结果。

## 4b. 更广的「状态 + 意图」范式（不限查询解耦）

查询解耦只是"意图 / 状态"分离的一种实现。行人轨迹预测领域还有四条同族路线，全部可以嫁接到我们的解码器上，而不必推翻 DeMo 的结构。

### 4b.1 五种范式对照

| 范式 | 代表工作 | 意图怎么表示 | 状态怎么表示 | 与我们解码器的关系 |
| --- | --- | --- | --- | --- |
| **查询解耦** | DeMo / DeMo++ [1][2] | 抽象 mode query 向量 | state query 逐时步 | **就是我们的结构** |
| **目标/终点条件化** | PECNet [6]、BiTraP [7] | **显式终点坐标** | 以终点为条件的轨迹生成 | 可嫁接：mode query 改为预测终点 |
| **多粒度由粗到细** | MGTraj [8]、TPNet [9]、TrajFine [10] | 粗粒度目标 | 中间粒度 → 细粒度递归精化 | 可嫁接：加时间锚点 + 精化 |
| **潜在意图变量** | SocialCVAE [11]、BiTraP [7] | CVAE 隐变量 z | 条件解码 | 与 WTA 功能重叠，收益有限 |
| **意图分类 + 回归多任务** | 多任务行人意图 [12] | 离散意图类别 | 轨迹回归 | 我们的 `pi` 头已是这一类 |

### 4b.2 与我们最大的结构性错配：没有显式终点

评估指标里 `minFDE20` / `FDE@1` **直接就是终点误差**。而我们的 mode query 是一个 128 维抽象向量，**没有任何显式终点表示**——终点只能由 `trajectory_mean_head` 的最后一帧间接涌现。

文献里所有 goal-guided 方法都在显式建模终点：

- **PECNet**（ECCV 2020）[6]："infers distant trajectory endpoints to assist in long-range multi-modal trajectory prediction"，并报告在 **ETH/UCY 上提升约 40.8%**、SDD 上约 20.9%。
- **BiTraP**（2020）[7]："estimates the goal (end-point) of trajectories and introduces a novel **bi-directional decoder** to improve longer-term trajectory prediction accuracy"——前向 + 以终点为条件的后向解码，专门解决长时域累积误差（≥2 秒）。
- **MGTraj**（2025）[8] 对两阶段范式的批评："Most goal-guided approaches decouple the prediction task into two stages: goal prediction and subsequent trajectory completion... which operate at **extreme granularities**... The potential utility of **intermediate temporal granularity remains largely unexplored**."

**这条观察比前面所有方案都更直接地指向指标结构**：我们花了五轮在编码器上找 1% 的改善，而终点从来没有被显式建模过。

### 4b.3 三个可嫁接的具体方案

**G1 · 终点显式化（对应 PECNet / BiTraP）**

```
mode query → 终点头（预测 K 个端点，相对 anchor 的偏移）
          → 端点作为条件注入耦合分支
耦合分支 → 生成 12 步轨迹（在端点条件下）
```

- 改动面：mode 分支加一个端点头；耦合分支的输入加端点条件（拼接或 FiLM）；
- 直接影响：`minFDE20`、`FDE@1`（终点误差）；
- 依据：[6][7] 在 ETH/UCY 上的量化收益；
- 风险：中。需要设计"端点如何注入"（concat / FiLM / 作为 query）。

**G2 · 中间粒度精化（对应 MGTraj 的 RRN）**

先在 3 个时间锚点（如 t=3/6/12）预测位置，再递归精化到全部 12 步。

- 依据：[8] 明确指出"中间时间粒度"是空白，且其权重共享的递归精化在 ETH/UCY 上取得 goal-guided 方法中的 SOTA；
- 改动面：耦合分支加 2–3 级精化头 + 权重共享；
- **撞车风险最高**：MGTraj 做的就是这件事。

**G3 · 速度辅助任务**

把逐帧速度作为辅助回归目标（[8] 的做法之一）。

- 改动面：一行辅助 loss；
- 风险：低；单独收益小，适合与 G1 组合。

### 4b.4 修正后的优先级

综合"对指标的直接性 × 撞车风险 × 改动成本"：

| 优先级 | 方案 | 直接影响的指标 | 撞车风险 | 判断 |
| --- | --- | --- | --- | --- |
| **1** | **G1 终点显式化** | minFDE20 / FDE@1 | 中-高（PECNet/BiTraP 是 2020 年工作，但"DeMo 式解耦 + 显式终点"的组合较少见） | **最值得做** |
| 2 | D1 耦合分支自精化 | 全部四项 | 高（DeMo++） | 可做，作 borrowed |
| 3 | D4 双头消融 | 无直接（结构清理） | 低 | 必做，成本最低 |
| 4 | G3 速度辅助 | 弱 | 低 | 顺手加 |
| 5 | G2 多粒度精化 | minFDE20 | **很高**（MGTraj 2025） | 只作对照 |
| 6 | D2/D3 query 去噪 / 组内 WTA | 间接 | 高 | 作 borrowed |
| 7 | G4 潜在意图变量 | 多样性 | 中 | 收益与 WTA 重叠，暂缓 |

**核心判断**：G1 之所以排第一，不是因为它最新，而是因为**它直接对准了指标的定义**——我们的 FDE 指标衡量终点，而模型里没有终点。这是唯一一处"结构缺陷与指标结构直接错配"的地方。

## 5. 撞车风险评估

| 方案 | 撞车风险 | 说明 |
| --- | --- | --- |
| **D1 自精化** | **高** | DeMo++ 已明确把 self-refinement 作为核心贡献。若我们的实现与其思路一致，**不能主张创新** |
| D2 DN-DETR 式去噪 | 高 | DETR 谱系标准技巧，行人轨迹预测中亦有应用 |
| D3 组内 WTA | 高 | Group DETR 直接对应 |
| D4 双头消融 | 低 | 属消融，不构成主张 |

**必须承认的定位**：这套解耦查询架构的**每一个主要改进方向都已有对口文献**。解码器不是当前的创新空间，而是"把已有技术补齐、拿工程数字"的空间。

如果论文需要创新点，仍然要回到观测证据条件化那条线（Stage 0–2 的教训说明那里也还没打通）；解码器优化的作用是**把 baseline 做强**，而不是提供贡献。

## 6. 一个必须注意的前提

`GAST-PF` 当前的参考数字是**旧 monitor 口径**（`val_minFDE20`），而新实验用 `val_new_minFDE20`。D1–D4 的任何结论都必须先补一条新口径的五场景 GAST-PF 基线，否则会重复 Stage 1/2 的"非配对对照"问题。
