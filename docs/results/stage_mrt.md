# GAST-PF-MRT · Middle Readout Token

_接在 Stage 2 之后的读出层探索；不属于路线文档预注册的 Stage 序列_

> **实现已移除**：当前 `src/` 中不再包含 `gast_middle_readout` 实现，runner/evaluator 也不再注册 `GAST-PF-MRT` 变体（已被 `GAST-PF-DAP` 取代）。本文件仅归档结果，代码不可从当前版本复现。

## 1. 实现（历史）

`gast_middle_readout=True`：在时间轴中点 `T//2` 插入一个 learned token，读取它的双向状态作为 actor 表示，替代原来的「固定读最后一个时间步」。同时在该位置插入中性衰减值（`neutral_decay=1`），避免衰减门控污染这个人工 token。

动机：末端缺失时，固定末端读出读到的是 gap-filled 占位状态；中点 token 让双向上下文从两侧汇总证据。

## 2. 协议

TrajGap-Bench Mixed-direct；seed=2024；K=20；100 epochs；batch size=64；选点 `val_new_minFDE20`；单种子 screening。样本合计 302,886。

训练：2026-10-18 18:50 起，两卡并行（GPU 1: ETH-M→UNIV-M→ZARA2-M；GPU 2: HOTEL-M→ZARA1-M）。`LAPLACE_LOSS_IMPL=vectorized-batch-v1`。全程 `Traceback=0 / CUDA错误=0 / OOM=0`。

## 4. 机制检验：否证

按 `terminal_missing`（样本加权）：

| 分组 | n | minFDE20 Δ | MR Δ |
| --- | ---: | ---: | ---: |
| `true`（末端缺失） | 135,417 | **+3.45%** | **+7.03%** |
| `false`（末端有效） | 167,469 | +2.71% | −4.92% |

按 `anchor_lag`：minFDE20 在 lag 0–4 全部变差，lag 5 为 **+8.82%**、lag 6 为 **+10.59%**，MR 在 lag 5 为 **+26.33%**、lag 6 为 **+27.53%**。

**缺失越严重退化越大，与「中点读出缓解末端缺失」的假设方向相反。**

## 5. 判定

**No-Go（作为机制主张）。** 与 Stage 2 FrameGeo、DAP 同属一类失败：读出/几何模块确实被模型使用，收益不落在机制预期的位置上。

保留的正面结果：ZARA2-M 相对 Stage 2 修复明显（ADE@1 −22.08%、FDE@1 −19.61%、MR −12.34%），当时把 Stage 2 在该场景的崩坏收了回来。
