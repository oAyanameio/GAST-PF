## 迭代与基线铁律（TrajGap-Bench）

- **统一 benchmark**：每个缺失历史迭代模型必须完整跑 TrajGap Mixed 五场景；Clean/SDD 只能作为单独扩展协议，不替代 TrajGap 主结果
- **滚动基线**：任一迭代在主指标上成为最优后，基线即刻更新为该模型，后续所有迭代从新基线出发、对照表以新基线为零点
- 当前缺失历史基线：**M0（optimizer-fix，2026-10-12 五场景重训完成）**（TrajGap-Bench Mixed；正式主榜指标为 minFDE20、minADE20；该轮旧 monitor 结果仅作历史参考）
- **M0 优化器基础配置（2026-10-11 起）**：AdamW 参数分组使用 `named_parameters(recurse=False)`；白名单外的自定义 mixer/RMSNorm weight 进入 no-decay，所有可训练参数恰好覆盖一次。更早的 M0 checkpoint/results 标记为 M0-pre-fix，不与修复后 M0 混称或作为同 revision 配对结果。

## 口径约束（全阶段适用）

- **表格铁律（2026-09-13）：所有实验表必须同时列出 minADE 与 minFDE**
- direct 与 impute 口径不并表；train_adapt 与 zero-shot 分开报告
- 每版本单变量增量，共享 M0-uni 骨干与优化配置；按 `val_new_minFDE20` 选 checkpoint，正式主指标为 `minFDE20` 与 `minADE20`；历史辅助诊断不进入主榜
- 阶段定义与验收门槛见《[选题](../research/选题.md)》§八
- **配对初始化纪律（2026-09-17 起）**：迭代模型与基线的对照必须共享同一初始 backbone state（生成 init ckpt 双方显式加载），杜绝构造分支导致的 RNG 流分叉；单种子对比尤其如此
- **取数陷阱**：同场景 Easy/Hard 的 M0 结果目录同名仅难度段不同，跨难度误取会伪造大幅提升/劣化；引用前核对 difficulty 字段
- **指标分裂检查（2026-09-17 起）**：top-1（ADE@1/FDE@1）与 best-of-K（minADE/minFDE）可能反向分裂；正式 benchmark 只以 `minADE20`、`minFDE20` 报告模型排序，其他诊断不能替代主指标或形成综合排名
